**REST API**

1. HTTP URL 是否正确（除了路径参数，需要带上请求参数）
   
2. 重点关注是否包含以下小节：
 - 是否可以直接使用，是否需要联系商务单独开通
 - 调用频率上限
 - 请求参数（HTTP URL 中 ？ 后面的参数）和路径参数不同，不要漏掉
 - 参数限制是否描述准确，是否有字符类型或大小的限制，多个值之间是否以逗号分隔
 - 是否有常见的错误码

3. 这个 API 调用后有什么影响，包括对客户端和服务端的影响以及这个API 与其他 API 之间的关系。

4. 示例代码是否准确，尤其注意 HTTP URL 是否准确，请求 body -d 是否包含。
   
5. HTTP 请求、请求示例以及响应示例中的 URL （如果有的话）需要保持一致。

**注意**

   1. GET 请求没有 Content-Type

   2. 请求示例中的 -L -X 等同于 -location -request
   
   3. -X 是指定请求method
   
   4. REST API 返回的状态码应该没有 3xx，是不需要重定向的
      -L 是跟随重定向的。
