# Receive Stream Messages

## Feature overview

EasyIM supports receiving streaming messages in one-to-one and group chats. A streaming message is generated, sent, and received progressively in real time. It is suitable for scenarios that output long text in segments, such as AI conversations, real-time collaborative writing, and progressively generated content.

Stream messages are generated by your app server and sent through the [RESTful API](/rest/message_stream_send_single.html). The iOS SDK receives, orders, merges, and returns them through callbacks. It does not allow clients to actively send streaming messages.

## Core concepts

Before continuing, familiarize yourself with the following core concepts:

- **Stream message**: A message transmission method that splits a complete message into multiple chunks and progressively sends and receives them in order.
- **Message chunk**: A single data segment in a streaming message. Multiple chunks form a complete message when combined in order.
- **Current chunk content**: The content of the single chunk received in the current callback. Retrieve it through `message.streamChunk.text`.
- **Cumulative merged content**: The complete content merged from the first chunk through the current chunk. Retrieve it through `EMTextMessageBody`.
- **Stream message transmission state**: The stage of a streaming message during transmission, such as started, in progress, complete, or ended with an error. Retrieve it through `EMStreamChunk`.
- **Finish reason code**: A business reason indicating why the streaming message ended. Retrieve it through `EMStreamChunk`.
- **Message ID**: The unique identifier for an entire streaming message. In the iOS SDK, retrieve it through `message.messageId`.

## Supported scope and limitations

- Conversation types: Only one-to-one and group chats are supported. Chat rooms are not supported.
- Message type: Only text streaming messages are supported.
- Sending method: Stream messages can be sent only through the [server-side RESTful API](/rest/message_stream_send_single.html).
- Client capabilities: The iOS SDK supports only receiving streaming messages, not sending them.

## Understand the tech

Stream messages are generated by your app server and delivered in chunks to the client SDK through the EasyIM server. The iOS SDK triggers a message callback as each chunk arrives and automatically merges the message content in chunk order. Use the current chunk information, cumulative merged content, and transmission state to update the UI in real time until the entire message completes or ends with an error.

## Integration process and examples

### Integration process

The basic process for receiving a streaming message is as follows:

1. After SDK initialization, register an `EMChatManagerDelegate` message listener.
2. Monitor `onStreamMessagesReceived`. When a new chunk arrives, the SDK orders the chunks and triggers this callback.
3. Iterate through the `EMChatMessage` objects received in the callback and use `msgId` to identify chunks of the same streaming message.
4. Call `message.streamChunk` to retrieve the current chunk information.
5. Call `EMTextMessageBody` to retrieve the cumulative content merged from the first chunk through the current chunk.
6. Update the UI based on `status` and stop rendering the streaming message when it completes or ends with an error.

### Example code

The following example shows how to register a message listener and receive streaming message chunks.

```swift
final class ChatViewController: UIViewController, EMChatManagerDelegate {

    override func viewDidLoad() {
        super.viewDidLoad()
        EMClient.shared().chatManager?.add(self, delegateQueue: nil)
    }

    func onStreamMessagesReceived(_ messages: [EMChatMessage]) {
        for message in messages {
            handleStreamChunk(message)
        }
    }
}
```

After receiving a streaming message chunk, retrieve information such as the current chunk content, transmission state, cumulative merged content, custom type, error code, and finish reason. Then update the display of the same message based on `message.messageId`.

```swift
private func handleStreamChunk(_ message: EMChatMessage) {
    let msgId = message.messageId

    guard let chunk = message.streamChunk else {
        return
    }

    // Handle the message or callback.
    let incrementText = chunk.text

    // Handle the message or callback.
    let status = chunk.status

    // Handle the message or callback.
    var fullText = ""
    if let body = message.body as? EMTextMessageBody {
        fullText = body.text
    }

    // Handle the message or callback.
    let customType = chunk.customType

    // Handle the message or callback.
    let errorCode = chunk.errorCode
    let finishReason = chunk.finishReason
    // Handle the message or callback.
}
```

## Message content and processing

After receiving a streaming message, process it based on the current chunk information, cumulative merged content, extensions, and transmission state.

### Current chunk information

Call `EMChatMessage` to retrieve an `streamChunk` object, which represents information about the currently received chunk.

| Method | Return type | Description |
| :--- | :--- | :--- |
| `text` | String | Retrieve the text content of the current chunk. |
| `status` | EMMessage.EMStreamStatus | Retrieve the transmission state of the streaming message corresponding to the current chunk. |
| `customType` | String | Retrieve the custom passthrough type, such as `"markdown"` for identifying the text format. |
| `errorCode` | Int | Retrieve the error code. The default value `0` indicates normal transmission. For other values, see [Error Codes](error.html). |
| `finishReason` | Int | Retrieve the finish reason code set by the app server. The default value `0` indicates no error. |

:::tip
 - `text` retrieves the current chunk content.
 - `EMTextMessageBody.text` retrieves the cumulative content merged from the first chunk through the current chunk.
 - We recommend displaying the cumulative merged content in the UI. To implement animation, use the current chunk content together with the cumulative merged content.
:::

```swift
private func handleStreamChunk(_ message: EMChatMessage) {
    if let chunk = message.streamChunk {
        let incrementText = chunk.text
        let status = chunk.status
    }
}
```

### Cumulative merged content

The SDK automatically merges streaming message content locally in chunk order and writes it to the message body.

`EMTextMessageBody.text` retrieves the cumulative content merged from the first chunk through the current chunk.

```swift
private func handleStreamChunk(_ message: EMChatMessage) {
    let chunk = message.streamChunk

    if let body = message.body as? EMTextMessageBody {
        let currentFullText = body.text
    }
}
```

:::tip
UI recommendations:
 - We recommend using the cumulative merged content for the final UI display.
 - For character-by-character or segment-by-segment animation, use the current chunk content together with the cumulative merged content.
:::

### Extension

Stream messages support the `ext` extension, but only the `ext` in the first chunk is persisted to the local database as the final value. Extensions in subsequent chunks are passed through by the server and must not be treated as the final message extensions.

:::tip
UI recommendations:
- Put extension information that applies to the entire message in the first chunk.
- Do not rely on dynamically updating `ext` in subsequent chunks to drive final business logic.
:::

### Transmission states and error handling

Call `EMStreamChunk` to retrieve the streaming message transmission state corresponding to the current chunk.

The `EMStreamChunkStatus` values are described below:

| State | Description | Recommended handling |
| :--- | :--- | :--- |
| `start` | The first chunk arrives and streaming message transmission begins. | Create or locate the corresponding message item, initialize its display, and mark the message as “Generating”. |
| `startAndComplete` | Stream message transmission completes in a single chunk, and the message contains only one chunk. | Display the content as a complete message and end stream rendering. |
| `progress` | The streaming message is being transmitted. | Continuously refresh the message with the cumulative merged content and keep the message in the “Generating” state. |
| `complete` | The last chunk arrives and streaming message transmission is complete. | Display the final merged content, end the “Generating” state, and process the message as complete. |
| `error` | Stream message transmission ends with an error. | Retain the content received so far, end stream rendering, and display an interrupted state or error prompt based on `errorCode` and `finishReason`.<br>- `errorCode == 0`: The SDK encountered no error.<br>- `errorCode != 0`: The streaming message ended abnormally. We recommend logging the event and prompting the user that “Content generation was interrupted”.<br>- `finishReason`: Define its business meaning on the server, such as normal completion, manual stop, timeout, or model error, and consistently map it to the corresponding client display text. |

Use cumulative merged content for UI rendering so users always see the latest complete text. For a streaming message that ends with an error, retain generated content and display a state such as “Interrupted”, “Generation failed”, or “Stopped” according to your business requirements.

## FAQ

#### 1. Can the SDK actively send streaming messages?

No. Stream messages [can be sent only through the server-side RESTful API](/rest/message_stream_send_single.html). The iOS SDK is responsible only for receiving them.

#### 2. What is the difference between `text` and `getMessage()`?

- `EMStreamChunk.text`: Current chunk content.
- `EMTextMessageBody.text`: The cumulative content merged from the first chunk through the current chunk.

The UI should generally display the value of `text`.

#### 3. How do I determine whether a message has ended?

Use any of the following methods:

- `status` is `complete`.
- `status` is `startAndComplete`.
- `status` is `error`.

#### 4. Why does `ext` in subsequent chunks not take effect?

Because only the `ext` in the first chunk is persisted as the final value. Subsequent chunks must not be used to update the final message extensions.

#### 5. Do I need to merge chunks myself?

The SDK automatically merges the content. However, the business layer should update the same message's UI based on `msgId` to avoid incorrectly displaying a single streaming message as multiple messages.
