# Receive Stream Messages

## Feature overview

EasyIM supports receiving stream messages in one-to-one and group chats. A stream message is generated, sent, and received progressively in real time. It is suitable for scenarios that output long text in segments, such as AI conversations, real-time collaborative writing, and progressively generated content.

Stream messages are generated by your app server and sent through the [RESTful API](/document/server-side/message_stream_send_single.html). The Android SDK receives, orders, merges, and returns them through callbacks. It does not allow clients to actively send stream messages.

## Core concepts

Before continuing, familiarize yourself with the following core concepts:

- **Stream message**: A message transmission method that splits a complete message into multiple chunks and progressively sends and receives them in order.
- **Message chunk**: A single data segment in a stream message. Multiple chunks form a complete message when combined in order.
- **Current chunk content**: The content of the single chunk received in the current callback. Retrieve it through `EMStreamChunk#getText()`.
- **Cumulative merged content**: The complete content merged from the first chunk through the current chunk. Retrieve it through `EMTextMessageBody#getMessage()`.
- **Stream message transmission state**: The stage of a stream message during transmission, such as started, in progress, complete, or ended with an error. Retrieve it through `EMStreamChunk#getStatus()`.
- **Finish reason code**: A business reason indicating why the stream message ended. Retrieve it through `EMStreamChunk#getFinishReason()`.
- **Message ID**: The unique identifier for an entire stream message. In the Android SDK, retrieve it through `EMMessage#getMsgId`.

## Supported scope and limitations

- Conversation types: Only one-to-one and group chats are supported. Chat rooms are not supported.
- Message type: Only text stream messages are supported.
- Sending method: Stream messages can be sent only through the [server-side RESTful API](/document/server-side/message_stream_send_single.html).
- Client capabilities: The Android SDK supports only receiving stream messages, not sending them.
- Message identifier: `msgId` identifies an entire stream message.
- Message limitations: For limits such as the total message length, chunk sending interval, and total transmission duration, see the [server-side API documentation](/document/server-side/message_stream_send_single.html#支持范围与限制).

## Understand the tech

Stream messages are generated by your app server and delivered in chunks to the client SDK through the EasyIM server. The Android SDK triggers a message callback as each chunk arrives and automatically merges the message content in chunk order. Use the current chunk information, cumulative merged content, and transmission state to update the UI in real time until the entire message completes or ends with an error.

## Integration process and examples

### Integration process

The basic process for receiving a stream message is as follows:

1. After SDK initialization, register an `EMMessageListener` message listener.
2. Monitor `onStreamMessageReceived`. When a new chunk arrives, the SDK orders the chunks and triggers this callback.
3. Iterate through the `EMMessage` objects received in the callback and use `msgId` to identify chunks of the same stream message.
4. Call `EMMessage#getStreamChunk()` to retrieve the current chunk information.
5. Call `EMTextMessageBody#getMessage()` to retrieve the cumulative content merged from the first chunk through the current chunk.
6. Update the UI based on `status` and stop rendering the stream message when it completes or ends with an error.

### Example code

The following example shows how to register a message listener and receive stream message chunks.

```java
EMMessageListener messageListener = new EMMessageListener() {
    @Override
    public void onMessageReceived(List<EMMessage> messages) {
        // Regular message callback.
    }

    @Override
    public void onStreamMessageReceived(List<EMMessage> messages) {
        // Stream message chunk callback.
        for (EMMessage message : messages) {
            handleStreamChunk(message);
        }
    }
};

EMClient.getInstance()
        .chatManager()
        .addMessageListener(messageListener);
```

Remove the listener when message events no longer need to be received:

```java
EMClient.getInstance()
        .chatManager()
        .removeMessageListener(messageListener);
```

After receiving a stream message chunk, retrieve information such as the current chunk content, transmission state, cumulative merged content, custom type, error code, and finish reason. Then update the display of the same message based on `msgId`.

```java
private void handleStreamChunk(EMMessage message) {
    String msgId = message.getMsgId();

    EMStreamChunk chunk = message.getStreamChunk();
    if (chunk == null) {
        return;
    }

    // Current chunk content.
    String incrementText = chunk.getText();

    // Current transmission state.
    EMMessage.EMStreamStatus status = chunk.getStatus();

    // Cumulative merged content.
    String fullText = "";
    if (message.getBody() instanceof EMTextMessageBody) {
        fullText = ((EMTextMessageBody) message.getBody()).getMessage();
    }

    // Custom type, such as text or markdown.
    String customType = chunk.getCustomType();

    // Determine whether the stream message has ended.
    boolean completed = chunk.isCompleted();

    // The error code is valid only in the ERROR state. The finish reason is set by the app server.
    int errorCode = chunk.getErrorCode();
    int finishReason = chunk.getFinishReason();
    // We recommend that the business layer update the same message's displayed content based on msgId.
}
```

## Message content and processing

After receiving a stream message, process it based on the current chunk information, cumulative merged content, extensions, and transmission state.

### Current chunk information

Call `EMMessage#getStreamChunk()` to retrieve an `EMStreamChunk` object, which represents information about the currently received chunk.

| Method | Return type | Description |
| :--- | :--- | :--- |
| `getText()` | String | Retrieve the text content of the current chunk. |
| `getStatus()` | EMMessage.EMStreamStatus | Retrieve the transmission state of the stream message corresponding to the current chunk. |
| `isCompleted()` | Boolean | Determine whether the stream message has ended.<br>When `getStatus()` returns `COMPLETE`, `START_AND_COMPLETE`, or `ERROR`, `isCompleted()` returns `true`. |
| `getCustomType()` | String | Retrieve the custom passthrough type, such as `"markdown"` for identifying the text format. |
| `getErrorCode()` | Int | Retrieve the error code. The default value `0` indicates normal transmission. For other values, see [Error Codes](error.html). |
| `getFinishReason()` | Int | Retrieve the finish reason code set by the app server. The default value `0` indicates no error. |

```java
private void handleStreamChunk(EMMessage message) {
    // Retrieve the current chunk content.
    EMStreamChunk chunk = message.getStreamChunk();
    if (chunk != null) {
        String incrementText = chunk.getText();
        EMMessage.EMStreamStatus status = chunk.getStatus();
    }
}
```

:::tip
 - `getText()` retrieves the current chunk content.
 - `EMTextMessageBody#getMessage()` retrieves the cumulative content merged from the first chunk through the current chunk.
 - We recommend displaying the cumulative merged content in the UI. To implement animation, use the current chunk content together with the cumulative merged content.
:::

### Cumulative merged content

The SDK automatically merges stream message content locally in chunk order and writes it to the message body.

`EMTextMessageBody#getMessage()` retrieves the cumulative content merged from the first chunk through the current chunk.

```java
private void handleStreamChunk(EMMessage message) {
    // 1. Retrieve the current chunk content.
    EMStreamChunk chunk = message.getStreamChunk();
    // 2. Retrieve the cumulative content merged from the first chunk through the current chunk.
    if (message.getBody() instanceof EMTextMessageBody) {
        String currentFullText = ((EMTextMessageBody)message.getBody()).getMessage();
    }
}
```

:::tip
UI recommendations:
 - We recommend using the cumulative merged content for the final UI display.
 - For character-by-character or segment-by-segment animation, use the current chunk content together with the cumulative merged content.
:::

### Extension

Stream messages support the `ext` extension, but only the `ext` in the first chunk is persisted to the local database as the final value. Extensions in subsequent chunks are passed through by the server and must not be treated as the final message extensions.

:::tip
Recommendations for using `ext`:
- Put extension information that applies to the entire message in the first chunk.
- Do not rely on dynamically updating `ext` in subsequent chunks to drive final business logic.
:::

### Transmission states and error handling

Call `EMStreamChunk#getStatus()` to retrieve the stream message transmission state corresponding to the current chunk.

The `EMStreamStatus` values are described below:

| State | Description | Recommended handling |
| :--- | :--- | :--- |
| `START` | The first chunk arrives and stream message transmission begins. | Create or locate the corresponding message item, initialize its display, and mark the message as “Generating”. |
| `START_AND_COMPLETE` | Stream message transmission completes in a single chunk, and the message contains only one chunk. | Display the content as a complete message and end stream rendering. |
| `PROGRESS` | The stream message is being transmitted. | Continuously refresh the message with the cumulative merged content and keep the message in the “Generating” state. |
| `COMPLETE` | The last chunk arrives and stream message transmission is complete. | Display the final merged content, end the “Generating” state, and process the message as complete. |
| `ERROR` | Stream message transmission ends with an error. | Retain the content received so far, end stream rendering, and display an interrupted state or error prompt based on `errorCode` and `finishReason`.<br>- `errorCode == 0`: The SDK encountered no error.<br>- `errorCode != 0`: The stream message ended abnormally. We recommend logging the event and prompting the user that “Content generation was interrupted”.<br>- `finishReason`: Define its business meaning on the server, such as normal completion, manual stop, timeout, or model error, and consistently map it to the corresponding client display text. |

Use cumulative merged content for UI rendering so users always see the latest complete text. For a stream message that ends with an error, retain generated content and display a state such as “Interrupted”, “Generation failed”, or “Stopped” according to your business requirements.

## FAQ

#### 1. Can the SDK actively send stream messages?

No. Stream messages [can be sent only through the server-side RESTful API](/document/server-side/message_stream_send_single.html). The Android SDK is responsible only for receiving them.

#### 2. What is the difference between `getText()` and `getMessage()`?

- `getText()`: The current chunk content.
- `getMessage()`: The cumulative content merged from the first chunk through the current chunk.

The UI should generally display the value of `getMessage()`.

#### 3. How do I determine whether a message has ended?

Use any of the following methods:

- `chunk.isCompleted()` returns `true`.
- `status` is `COMPLETE`.
- `status` is `START_AND_COMPLETE`.
- `status` is `ERROR`.

#### 4. Why does `ext` in subsequent chunks not take effect?

Because only the `ext` in the first chunk is persisted as the final value. Subsequent chunks must not be used to update the final message extensions.

#### 5. Do I need to merge chunks myself?

The SDK automatically merges the content. However, the business layer should update the same message's UI based on `msgId` to avoid incorrectly displaying a single stream message as multiple messages.
