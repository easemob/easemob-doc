# Chat Room Messages

## Use cases

- Communication in a multi-user chat room: Members communicate by sending and receiving messages in the chat room.
- An app admin sends messages to a chat room: An app admin calls a RESTful API to send messages in the chat room.

## Message types

| Type     | Description                             |
| :------------- | :----------------------------------------------------------- |
| Text message    | A text message contains text, including hyperlinks and emojis. Emoji messages are implemented using text messages.<br/> The size limit for a text message is 5 KB. |
| Location message    | A location message requires a third-party map service to provide latitude and longitude information. After receiving a location message, the recipient can use this information to display the location with a third-party map service. |
| Command message    | A command message can be regarded as an instruction. By sending the command, the sender notifies the recipient of an operation to perform. After receiving the message, the recipient's system can process it as needed.<br/> - Command messages are not displayed in the UI.<br/> - The message size limit is 5 KB.<br> - You can use command messages to update avatars and nicknames or synchronize status.<br/> Command messages are not stored in the local database. |
| Image message    | An image message is an attachment message. You must first upload the image to the message server. When the recipient receives the image message, the image thumbnail is downloaded automatically.<br/> By default, the image cannot exceed 10 MB. The size limit for an image message is 5 KB. |
| Voice message    | A voice message is an attachment message. You must first upload the voice file to the message server. When the recipient receives the voice message, the voice file is downloaded automatically.<br/> By default, the audio file cannot exceed 10 MB. The size limit for a voice message is 5 KB. |
| Video message    | A video message is an attachment message. You must first upload the video to the message server. When the recipient receives the video message, the video thumbnail is downloaded automatically. The recipient can click the message to download the video.<br/> - On the Web client, video messages do not have thumbnails.<br/> - By default, the video file cannot exceed 10 MB. The size limit for a video message is 5 KB. |
| File message    | A file message is an attachment message. You must first upload the file to the message server.<br/> The attachment cannot exceed 10 MB. The size limit for a file message is 5 KB. |
| Custom message   | A message type defined by the developer. You can set a type name for a custom message and add multiple custom message types.<br/> - The size limit for a custom message is 5 KB.<br/> - Custom messages can be used for red packet messages, template messages, and other scenarios. |
| Streaming message     |A streaming message is a real-time messaging mechanism in which content is generated, sent, and received simultaneously. Streaming messages are generated by the business server and sent through a RESTful API. The SDK receives, sorts, merges, and delivers callbacks for these messages, but does not allow the client to actively send them. |

:::tip
1. By default, message attachments, such as images, audio, video, and other files, cannot exceed 10 MB and can be stored for 7 days. To increase either limit, contact the EasyIM business manager.
2. If the basic message types do not meet your requirements, you can enhance them with custom message extensions. A typical use case is sending a message that quotes an earlier text or image message. After an extension is added, the message cannot exceed the size limit of the original message type. 
:::

## Chat room message capabilities

| Type    | Description       | Use case    |
| ---------- | ---------------- | --------------------------- |
| Send regular chat room messages           | Chat room members can send messages through an EasyIM SDK API. An app admin can call a RESTful API to send messages in any chat room without joining it. | Chat room members send messages in the chat room, or an app admin sends messages to any chat room           |
| Receive online chat room messages   | Chat room members can receive online chat room messages through an EasyIM SDK    | Online chat room members receive chat room messages in real time   |
| Chat room members retrieve historical messages  | Chat room members query historical messages through an EasyIM SDK API. <br/> You must upgrade the SDK to the specified version and contact the EasyIM business manager to activate this feature.                        | Chat room members view chat room history                 |
| App server retrieves chat room messages       | <br/> - An app admin can use a RESTful API to download all messages generated by the app during a specified period;<br/> - An app admin can use a RESTful API to retrieve the chat history of any chat room;<br/> - An app server can obtain chat room messages in real time through chat room message sending callbacks. | <br/> - The app regularly backs up chat history;<br/> - The app needs to retrieve historical messages from a chat room;<br/> - The app needs to obtain chat room messages in real time |
| Include sender information in chat room messages | Include the sender's nickname, avatar, and user- or chat-room-related custom fields in a chat room message through message extension fields | Display the message sender's nickname, avatar, and other user information      |
| Control chat room message sending   | Control message sending through muting, pre-delivery callbacks for chat room messages, blocklists, and content moderation.  | <br/> - Prevent a member from sending messages in the chat room<br/> - Prevent all chat room members from sending messages in the chat room<br/> - The app server filters or modifies messages |
| Control chat room message frequency    | For a single app, the RESTful API has the following 3 limits:<br/> - 10 chat rooms/call  <br/> - 100 messages/second <br/> -  100 calls/second | Control API calls  |

:::tip
Unlike group chats, chat rooms do not support offline push.
:::

## Chat room message sending controls

| Chat room message sending control   | Description  |
| :--------- | :----- |
| Message priority | You can set the priority of a chat room message to high, normal, or low. When a large number of messages are sent concurrently in a chat room or the message sending frequency is too high, the server discards low-priority messages first and prioritizes the delivery of high-priority messages.  |
| Priority message sending (chat room allowlist)| Messages sent in a chat room by members on the chat room allowlist have a high priority and are delivered first, but delivery is not guaranteed. Under high load, the server discards low-priority messages first. If the load remains high, the server also discards high-priority messages. |
| Prevent message sending  |  - **Blocklist**: After a member is added to the blocklist, the member is removed from the chat room and can no longer send or receive messages.<br/> - **Mute**: After a member is added to the mute list, the member cannot send messages in the chat room even if added to the allowlist, but can receive messages normally. After **mute all** is enabled, only members on the allowlist can send messages.<br/> - **Global mute (RESTful API)**: After a user is globally muted, the user cannot send one-to-one messages or messages in any chat group or chat room. A globally muted member cannot send messages in any one-to-one chat, chat group, or chat room even if added to a chat room allowlist.|
|Allow or intercept messages|- **Pre-delivery callback**: Before sending a message, the EasyIM server sends a request to your app server. You can configure rules based on your business requirements to determine whether to deliver or intercept the message.<br/> - **Content moderation**: Process messages based on content moderation results, including intercepting messages, replacing sensitive information, and allowing messages. This service applies only to text, image, audio, and video messages. |

- SDK

  By default, the SDK does not limit the frequency at which an individual user can send messages. If you contact the EasyIM business manager to configure this limit, the SDK reports an error when a user's chat room message sending frequency exceeds it. For example, the Android SDK reports error code 509 `MESSAGE_CURRENT_LIMITING`.
