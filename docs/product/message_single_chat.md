# One-to-One Messages

## Use cases

- One-to-one chats in an app: Two users have a private one-to-one chat.
- An app admin sends messages to users: An app admin calls a RESTful API to send messages to app users or sends messages as another user.
  
## Message types

| Type      | Description          |
| :------------- | :----------- |
| Text message       | A text message contains text, including hyperlinks and emojis. Emoji messages are implemented using text messages.<br/> The size limit for a text message is 5 KB. |
| Location message       | A location message requires a third-party map service to provide latitude and longitude information. After receiving a location message, the recipient can use this information to display the location with a third-party map service. |
| Command message       | A command message can be regarded as an instruction. By sending the command, the sender notifies the recipient of an operation to perform. After receiving the message, the recipient's system can process it as needed. Command messages are not displayed in the UI.<br/>The message size limit is 5 KB.<br> You can use command messages to update avatars and nicknames or synchronize status.<br/> Command messages are not stored in the local database. |
| Image message       | An image message is an attachment message. You must first upload the image to the message server. When the recipient receives the image message, the image thumbnail is downloaded automatically.<br/> By default, the image cannot exceed 10 MB. The size limit for an image message is 5 KB. |
| Voice message       | A voice message is an attachment message. You must first upload the voice file to the message server. When the recipient receives the voice message, the voice file is downloaded automatically.<br/> By default, the audio file cannot exceed 10 MB. The size limit for a voice message is 5 KB. |
| Video message       | A video message is an attachment message. You must first upload the video to the message server. When the recipient receives the video message, the video thumbnail is downloaded automatically. The recipient can click the message to download the video. On the Web client, video messages do not have thumbnails.<br/> By default, the video file cannot exceed 10 MB. The size limit for a video message is 5 KB. |
| File message       | A file message is an attachment message. You must first upload the file to the message server.<br/> The attachment cannot exceed 10 MB. The size limit for a file message is 5 KB. |
| Custom message     | A message type defined by the developer. You can set a type name for a custom message and add multiple custom message types.<br/>The size limit for a custom message is 5 KB.<br/>Custom messages can be used for red packet messages, template messages, and other scenarios. |
| Streaming message     |A streaming message is a real-time messaging mechanism in which content is generated, sent, and received simultaneously. Streaming messages are generated by the business server and sent through a RESTful API. The SDK receives, sorts, merges, and delivers callbacks for these messages, but does not allow the client to actively send them. |


:::tip
<br/> - By default, message attachments, such as images, audio, video, and other files, cannot exceed 10 MB and can be stored for 7 days. To increase either limit, contact the EasyIM business manager.<br/> - If the basic message types do not meet your requirements, you can enhance them with custom message extensions. A typical use case is sending a message that quotes an earlier text or image message. After an extension is added, the message cannot exceed the size limit of the original message type.
:::

## Message sending controls

| One-to-one message sending control      | Description   |
| :--------- | :----- |
| Send messages between non-friends | Any two users in an app can send one-to-one messages to each other. In this scenario, **Friend Relationship Check** is disabled on the **Chat** > **Features** >**User & Login** page of the EasyIM Console. |
| App admin sends one-to-one messages  | An app admin sends messages to any user in the app as another user. |
| Send messages only to friends  | Users can send messages only to friends. In this scenario, **Friend Relationship Check** is enabled on the **Chat** > **Features** >**User & Login** page of the EasyIM Console. |
| Reject messages from a user | You can reject messages from a user in the following ways:<br/> - **Add the user to the blocklist** to reject messages from the user.<br/> - **Remove the user from the friend list.** This method applies when an app allows messages only between friends. If the app allows messages between non-friends, user A can still send a message to user B after user A is removed from user B's friend list.<br/> - **Global mute (RESTful API)**: Globally mute a specified user in one-to-one chats so that the user cannot send one-to-one messages to any user in the app.|
|Allow or intercept messages|- **Pre-delivery webhook**: Before sending a message, the EasyIM server sends a request to your app server. You can configure rules based on your business requirements to determine whether to deliver or intercept the message.<br/> - **Content moderation**: Process messages based on content moderation results, including intercepting messages, replacing sensitive information, and allowing messages. This service applies only to text, image, audio, and video messages. |

### SDK

By default, the SDK does not limit the frequency at which an individual user can send messages. If you contact the EasyIM business manager to configure this limit, the SDK reports an error when a user's one-to-one message sending frequency exceeds it. For example, the Android SDK reports error code 509 `MESSAGE_CURRENT_LIMITING`.
