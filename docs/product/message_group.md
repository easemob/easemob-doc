# Chat Group Messages

## Use cases

- Communication in a multi-user chat group: Members communicate by sending and receiving messages in the chat group.
- An app admin sends messages to a chat group: An app admin calls a RESTful API to send messages in the chat group.

## Message types

| Type          | Description                                                         |
| :------------- | :----------------------------------------------------------- |
| Text message       | A text message contains text, including hyperlinks and emojis. Emoji messages are implemented using text messages.<br/> The size limit for a text message is 5 KB. |
| Location message       | A location message requires a third-party map service to provide latitude and longitude information. After receiving a location message, the recipient can use this information to display the location with a third-party map service. |
| Command message       | A command message can be regarded as an instruction. By sending the command, the sender notifies the recipient of an operation to perform. After receiving the message, the recipient's system can process it as needed. Command messages are not displayed in the UI.<br/>The message size limit is 5 KB.<br> You can use command messages to update avatars and nicknames or synchronize status.<br/> Command messages are not stored in the local database. |
| Image message       | An image message is an attachment message. You must first upload the image to the message server. When the recipient receives the image message, the image thumbnail is downloaded automatically.<br/> By default, the image cannot exceed 10 MB. The size limit for an image message is 5 KB. |
| Voice message       | A voice message is an attachment message. You must first upload the voice file to the message server. When the recipient receives the voice message, the voice file is downloaded automatically.<br/> By default, the audio file cannot exceed 10 MB. The size limit for a voice message is 5 KB. |
| Video message       | A video message is an attachment message. You must first upload the video to the message server. When the recipient receives the video message, the video thumbnail is downloaded automatically. The recipient can click the message to download the video. On the Web client, video messages do not have thumbnails.<br/> By default, the video file cannot exceed 10 MB. The size limit for a video message is 5 KB. |
| File message       | A file message is an attachment message. You must first upload the file to the message server.<br/> The attachment cannot exceed 10 MB. The size limit for a file message is 5 KB. |
| Custom message     | A message type defined by the developer. You can set a type name for a custom message and add multiple custom message types.<br/>The size limit for a custom message is 5 KB.<br/>Custom messages can be used for red packet messages, template messages, and other scenarios. |
| Streaming message     |A streaming message is a real-time messaging mechanism in which content is generated, sent, and received simultaneously. Streaming messages are generated by the business server and sent through a RESTful API. The SDK receives, sorts, merges, and delivers callbacks for these messages, but does not allow the client to actively send them. |

:::tip

1. By default, message attachments, such as images, audio, video, and other files, cannot exceed 10 MB and can be stored for 7 days. To increase either limit, contact the EasyIM business manager.
2. If the basic message types do not meet your requirements, you can enhance them with custom message extensions. A typical use case is sending a message that quotes an earlier text or image message. After an extension is added, the message cannot exceed the size limit of the original message type.
3. The size and storage period limits for message attachments are the same as those for chat group shared files. If a limit for message attachments is increased, the corresponding limit for chat group shared files is automatically adjusted accordingly, and vice versa.
   
:::

## Message capabilities

| Type    | Description       | Use case    |
|  :--------- |  :--------- |  :--------- |
| Send regular chat group messages           | Chat group members can send messages through an EasyIM SDK API. An app admin can call a RESTful API to send messages in any chat group without joining it. | Chat group members send messages in the chat group, or an app admin sends messages to any chat group           |
| Offline push for chat group messages           | Support APNs and FCM offline push   | Offline push for chat group messages                                             |
| Receive online chat group messages   | Chat group members can receive online chat group messages through an EasyIM SDK                       | Online chat group members receive chat group messages in real time                                     |
| Chat group members retrieve offline or historical messages  | Chat group members query historical messages through an EasyIM SDK API                           | Chat group members receive offline messages when they get online or view chat group history                 |
| App server retrieves chat group messages       | <br/> - An app admin can use a RESTful API to download all messages generated by the app during a specified period;<br/> - An app admin can use a RESTful API to retrieve the chat history of any chat group;<br/> - An app server can obtain chat group messages in real time through chat group message sending callbacks. | <br/> - The app regularly backs up chat history;<br/> - The app needs to retrieve historical messages from a chat group;<br/> - The app needs to obtain chat group messages in real time |
| Delete messages  | Delete historical messages by calling a RESTful API or SDK API   | <br/> - Prevent the spread of malicious information<br/> - Protect privacy<br/> - Manage storage space |
| Include sender information in chat group messages | Include the sender's nickname, avatar, and user- or chat-group-related custom fields in a chat group message through message extension fields | Display the message sender's nickname, avatar, and other user information      |
| Control chat group message sending   | Control message sending through muting, banning the chat group, pre-delivery callbacks for chat group messages, blocklists, and content moderation.  | <br/> - Prevent a member from sending messages in the chat group<br/> - Prevent all chat group members from sending messages in the chat group<br/> - The app server filters or modifies messages |
| Control chat group message reception  | <br/> - A user can block messages from a chat group through an SDK API <br/> - Ban a chat group through a RESTful API| <br/> - A user no longer receives messages from a chat group<br/> - Prevent all members of a chat group from sending and receiving messages in it  |
| Control chat group message frequency    | <br/>For a single app, the RESTful API has the following 3 limits:<br/> - 20 messages/second/App Key  <br/> - 20 calls/second <br/> -  3 chat groups/call.| Prevent overly frequent RESTful API calls. To increase these limits, contact the EasyIM business manager.  |

## Message sending controls

| Chat group message sending control     | Description   |
| :--------- | :----- |
| Prevent message sending  |  - **Blocklist**: After a member is added to the blocklist, the member is removed from the chat group and can no longer send or receive messages.<br/> - **Mute**: After a member is added to the mute list, the member cannot send messages in the chat group even if added to the allowlist, but can receive messages normally. After **mute all** is enabled, only members on the allowlist can send messages.<br/> - **Global mute (RESTful API)**: After a user is globally muted, the user cannot send one-to-one messages or messages in any chat group or chat room. A globally muted member cannot send messages in any one-to-one chat, chat group, or chat room even if added to a chat group or chat room allowlist.|
|Allow or intercept messages|- **Pre-delivery callback**: Before sending a message, the EasyIM server sends a request to your app server. You can configure rules based on your business requirements to determine whether to deliver or intercept the message.<br/> - **Content moderation**: Process messages based on content moderation results, including intercepting messages, replacing sensitive information, and allowing messages. This service applies only to text, image, audio, and video messages. |

### SDK

By default, the SDK does not limit the frequency at which an individual user can send messages. If you contact the EasyIM business manager to configure this limit, the SDK reports an error when a user's group chat message sending frequency exceeds it. For example, the Android SDK reports error code 509 `MESSAGE_CURRENT_LIMITING`.
