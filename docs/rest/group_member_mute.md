# Mute Specified Chat Group Members

## Feature overview

- Add one or more chat group members to the mute list to mute them temporarily or permanently.
- A temporary mute expires automatically. To remove a permanent mute, [call the unmute API](group_member_unmute.html).
- A muted member can receive and view messages sent by other users in the chat group but cannot send messages.
- You can mute up to 100 chat group members at a time.
- A muted chat group member cannot send messages in the chat group or its message threads.
- Members on the chat group mute list cannot send messages even if they are added to the chat group allowlist.
- If a muted member leaves and then rejoins the same chat group before the mute expires, the mute remains in effect.
- Muting or unmuting all members does not affect the chat group's mute list.
- Muting a chat group member triggers a post-delivery callback. For details, see [Chat Group Member Added to the Mute List](callback_group_room_mute.html#add-a-member-to-the-mute-list).

## Call frequency limit

100 calls/second/App Key

## Request URL

```http
POST https://{host}/{org_name}/{app_name}/chatgroups/{group_id}/mute
```

| Parameter     | Type   | Required | Description                                                        |
| :------- | :----- | :------- | :---------------------------------------------------------- |
| `group_id`  | Int    |  Yes       | Chat group ID. |

For descriptions of other parameters in the request URL, see [Request URL parameters](overview.html#request-url).

## Request example

```shell
# Replace <YourAppToken> with the App Token generated on your server

curl -X POST https://XXXX/XXXX/XXXX/chatgroups/10XXXX85/mute   \
-H 'Authorization: Bearer <YourAppToken>'  \
-d '{"usernames":["user1"], "mute_duration":1000}' 
```

## Request header fields

For a description of the `Authorization` field, see [Request header fields](overview.html#request-header-fields).

## Request body fields

| Parameter            | Type  | Required | Description                                                       |
| :-------------- | :---- | :------- | :--------------------------------------------------------- |
| `usernames`     | Array | Yes       | A list of user IDs to add to the mute list. You can specify up to 100 user IDs at a time. |
| `mute_duration` | Long  | Yes       | Mute duration in milliseconds. For example, `1000` mutes the members for 1 second. <br/>`0` removes the mute, and `-1` mutes the members permanently. |

## Response body fields

If the returned HTTP status code is `200`, the request is successful. The response body contains the following fields:

| Field          | Type   | Description                                                            |
| :------------ | :----- | :-------------------------------------------------------------- |
| `data` | JSON Array | Response data.|
|  - `result` | Bool   | Whether the member was muted successfully: <br/> - `true`: The member was muted; <br/> - `false`: The member was not muted. |
|  - `expire` | Long   | Mute expiration time as a Unix timestamp in milliseconds. |
|  - `user`   | String | The user ID of the muted member. |

The other fields are described below:

| Field          | Type | Description                                                                              |
| :------------ | :--- | :-------------------------------------------------------------------------------- |
| `action`          | String | Request method. |
| `application`     | String | Unique identifier of the app in the system. It is generated by the system and does not require your attention. |
| `uri`             | String | Request URL. |
| `entities`        | JSON Array   | Response entities. |
| `timestamp`       | Long   | Unix timestamp in milliseconds. |
| `duration`        | Int    | Duration from sending the request to receiving the response, in milliseconds. |
| `organization`    | String | Unique identifier assigned by EasyIM to each company (organization), identical to the `org_name` request parameter. |
| `applicationName` | String | App name entered when you created the app in the Easemob Console, identical to the `app_name` request parameter. |

## Error code

If the returned HTTP status code is not `200`, the request fails and one of the following error codes may be returned:

| HTTP status code        | Error type | Error message          | Possible cause | Recommendation |
| :----------- | :--- | :------------- | :----------- | :----------- |
| 401     | unauthorized | Unable to authenticate (OAuth) | The token is invalid, expired, or incorrect. | Use a new token. |
| 403     | forbidden_op | users [XX] are not members of this group! | The user to mute is not in the chat group. | Specify the user ID of a chat group member. |
| 404     | resource_not_found | grpID XX does not exist! | The chat group does not exist. | Use a valid chat group ID. |
| 400     | invalid_parameter | userNames size is more than max limit : 100 | More than 100 chat group members were specified. | Specify no more than 100 chat group members. |
| 403    | forbidden_op   | "forbidden operation on group owner!"   | Group owners cannot be muted.  |

For other errors, see [Response status codes](error.html) for possible causes.
