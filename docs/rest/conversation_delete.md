# Delete a Conversation for One User

## Feature overview

- You can delete a conversation from the server for one user and specify whether to delete its roaming messages from the server.
- After the conversation is deleted, that user can no longer retrieve it from the server. Other users participating in the conversation can still retrieve its content from the server.
- This API currently supports one-to-one and group chat conversations.

## Request URL

```http
DELETE https://{host}/{org_name}/{app_name}/users/{username}/user_channel
```

| Parameter       | Type   | Required | Description        |
| :--------- | :----- | :------- | :--------------- |
| `username` | String | Yes       | Unique identifier, or user ID, of the user for whom to delete the conversation. |

For details about other parameters in the request URL, see [Request URL parameters](overview.html#request-url).

## Request example

```shell
# Replace <YourAppToken> with the App Token generated on your server
curl -X DELETE 'https://XXXX/XXXX/XXXX/users/u1/user_channel' \
-H 'Authorization: Bearer <YourAppToken>'  \
-H 'Content-Type: application/json'  \
-H 'Accept: application/json'  \
-d '

{ "channel": "u2", "type": "chat", "delete_roam": true }
'
```

## Request header fields

For details about the `Content-Type`, `Accept`, and `Authorization` fields, see [Request header fields](overview.html#request-header-fields).

## Request body fields

| Parameter          | Type   | Required | Description   |
| :------------ | :----- | :------- | :------------------------- |
| `channel`     | String | Yes       | ID of the conversation to delete. The value depends on the conversation type specified by `type`:<br/> - If `type` is `chat`, indicating a one-to-one chat, the conversation ID is the peer user's ID.<br/> - If `type` is `groupchat`, indicating a group chat, the conversation ID is the chat group ID. |
| `type`        | String | Yes       | Conversation type.<br/> - `chat`: One-to-one chat conversation.<br/> -`groupchat`: Group chat conversation.       |
| `delete_roam` | Bool   | Yes       | Whether to delete the conversation's roaming messages from the server.<br/> - `true`: Yes. If the server-side messages in the conversation are deleted, the user cannot retrieve its roaming messages from the server.<br/> - `false`: No. The user can still retrieve the conversation's roaming messages from the server. |

## Response example

```json
{
  "path": "/users/user_channel",
  "uri": "https://XXXX/XXXX/XXXX/users/u1/user_channel",
  "timestamp": 1638440544078,
  "organization": "XXXX",
  "application": "c3624975-XXXX-XXXX-9da2-ee91ed4c5a76",
  "entities": [],
  "action": "delete",
  "data": {
    "result": "ok"
  },
  "duration": 3,
  "applicationName": "XXXX"
}
```

## Response body fields

If the returned HTTP status code is `200`, the request is successful. The `data` field in the response body is described below:

| Parameter              | Type   | Description          |
| :---------------- | :----- | :------------------------------- |
| `data`          | JSON | Deletion result details.                                                                     |
| `data.result`          | String | Deletion result. `ok` indicates success. If the operation fails, the error code and reason are returned directly.            |

The other fields in the response body are described below:

| Parameter              | Type   | Description          |
| :---------------- | :----- | :------------------------------- |
| `path`            | String | Request path, which is part of the request URL and does not require your attention.                              |
| `uri`             | String | Request URL. |
| `timestamp`       | Long   | Unix timestamp of the HTTP response, in milliseconds.                                          |
| `organization`    | String | Unique identifier assigned by EasyIM to each company (organization), identical to the `org_name` request parameter. |
| `application`     | String | Unique identifier of the app in the system. It is generated by the system and does not require your attention. |
| `entities`        | JSON Array   | Response entities. |
| `action`          | String | Request method. |
| `duration`        | Int    | Duration from sending the HTTP request to receiving the response, in milliseconds.                                     |
| `applicationName` | String | App name entered when you created the app in the Easemob Console, identical to the `app_name` request parameter. |

If the returned HTTP status code is not `200`, the request fails. See [Response status codes](error.html) for possible causes.

## Error code

If the returned HTTP status code is not `200`, the request fails and one of the following error codes may be returned:

| HTTP status code | Error type               | Error message                  | Possible cause             | Recommendation      |
|:---------|:-------------------|:----------------------|:-----------------|:----------|
| 400      | invalid_request_body    | Request body is invalid. Please check body is correct. | The request body is malformed.  | Check whether the request body is valid, including whether field types are correct.    |
| 400      | illegal_argument | field channel cannot be null or empty | The request parameter `channel` is an empty string. | Enter the correct request parameter `channel`.|
| 400      | illegal_argument | field type cannot be null or empty | The request parameter `type` is an empty string. | Enter the correct request parameter `type`. |
| 400      | illegal_argument | field delete_roam cannot be null | The request parameter `delete_roam` is empty. | Enter the correct request parameter `delete_roam`. |

For other errors, see [Response status codes](error.html) for possible causes.
