# Send One-to-One Stream Messages

## Feature overview

EasyIM supports receiving streaming messages in one-to-one chats and group chats. A streaming message is generated, sent, and received incrementally in real time. It is suitable for scenarios where long text is output in segments, such as AI conversations, real-time collaborative writing, and displays of incrementally generated content.

Stream messages are generated by your business server and sent through the RESTful API. [The SDK receives, sorts, combines, and delivers callbacks for them](/sdk/v5/android/message_stream_receive.html). Clients cannot actively send streaming messages.

## Core concepts

Before continuing, familiarize yourself with these core concepts:

- **Stream message**: A message transmission method that splits a complete message into multiple chunks, which are sent and received incrementally in order.
- **Message chunk**: An individual data segment in a streaming message. Multiple chunks are combined in order to form a complete message.
- **`msgId`**: Message ID. The unique identifier of the entire streaming message.
- **seq**: Message chunk identifier. A streaming message is split into multiple chunks that are sent in order. The first chunk has sequence number `0`, and subsequent sequence numbers increase incrementally so that the chunks can be combined into the original message.
- **finish**: Indicates whether the current chunk is the last one.

## Supported scope and limitations

- Conversation types: Only one-to-one chats and group chats are supported. Chat rooms are not supported.
- Message type: Only text streaming messages are supported.
- Sending method: Messages can only be sent through the [server-side RESTful API](/rest/message_stream_send_single.html).
- Client capability: [The SDK only supports receiving streaming messages](/sdk/v5/android/message_stream_receive.html), not sending them.
- Message identifier: `msgId` identifies the entire streaming message.
- Message limitations: The following limitations apply when sending a streaming message:
  - **Chunk interval**: The interval between adjacent chunks cannot exceed 30 seconds. A timeout returns [error 14033](#error-code) and terminates the streaming message.
  - **Total transmission duration**: The total transmission duration of all chunks cannot exceed 30 minutes. Sending another chunk after the timeout returns [error 14034](#error-code).
  - **Total length**: The combined text content of all chunks cannot exceed 128 KB. Exceeding this limit returns [error 14032](#error-code) and terminates the streaming message.
  - **After termination**: After a streaming message is terminated, all subsequent requests to send its chunks are rejected.

## Call the API to send one-to-one streaming messages

### Call frequency limit

100 messages/second/App Key

### Request URL

```http
POST https://{host}/{org_name}/{app_name}/stream_message/user
```

For details about the parameters in the request URL, see [Request URL parameters](overview.html#request-url).

### Request example

For example, a streaming message contains three message chunks. The request example for each chunk is shown below.

- Send the first message chunk:

When sending a single-chunk streaming message, where the entire message consists of only one chunk, set `finish` to `true` to indicate that the transmission is complete. If needed, you can also include `finishReason` to specify why the transmission ended.

```bash
# Replace <YourAppToken> with the App Token generated on your server
curl -X POST -i 'https://XXXX/XXXX/XXXX/stream_message/user' \
-H 'Content-Type: application/json' \
-H 'Accept: application/json' \
-H 'Authorization: Bearer <YourAppToken>'  \
-d '{
    "from": "111",
    "to": "222",
    "body": {
        "msg": "第一个分片",
        "seq": 0,
        "type": "markdown"
    },
    "ext": {
    }
}'
```

- Send the second message chunk:

```bash
curl -X POST -i 'https://XXXX/XXXX/XXXX/stream_message/user' \
-H 'Content-Type: application/json' \
-H 'Accept: application/json' \
-H 'Authorization: Bearer <YourAppToken>'  \
-d '{
    "from": "111",
    "to": "222",
    "body": {
        "msgId": "1499696395467098072",
        "msg": "第二个分片",
        "seq": 1,
        "finish": false,
        "finishReason": 0,
        "type": "markdown"
    }
}'
```

- Send the last message chunk:
  
```bash
curl -X POST -i 'https://XXXX/XXXX/XXXX/stream_message/user' \
-H 'Content-Type: application/json' \
-H 'Accept: application/json' \
-H 'Authorization: Bearer <YourAppToken>'  \
-d '{
    "from": "111",
    "to": "222",
    "body": {
        "msgId": "1499696395467098072",
        "msg": "third chunk",
        "seq": 2,
        "finish": true,
        "finishReason": 1,
        "type": "markdown"
    }
}'
```

### Request header fields

For details about the `Content-Type`, `Accept`, and `Authorization` fields, see [Request header fields](overview.html#request-header-fields).

### Request body fields

| Parameter | Type   | Required | Description     |
| :-------------- | :----- | :----------------- | :-------------------- |
| `from` | String | Yes   | User ID of the message sender. The default is `admin`.<Container type="tip" title="Note"><br/>- The server does not verify whether this user ID exists. Even if you specify a nonexistent ID, the message is still delivered normally.<br/>- The server does not check whether the recipient has added the sender to the blocklist or whether the sender is muted.<br/>- If you pass an empty string (""), the request fails.</Container> |
| `to`   | String | Yes   | User ID of the message recipient.<br/><Container type="tip" title="Note">The server does not verify whether this user ID exists. Even if you specify a nonexistent ID, the message is still delivered normally.</Container> |
| `body` | JSON   | Yes   | Message content. See the `body` parameter details below.                        |
| `ext`  | JSON   | No   | Message extension field for passing custom data. It cannot be `null`. The server uses the `ext` value from the **first chunk** and passes this field through for subsequent chunks.|

The fields in `body` in the request body are described below.

| Parameter | Type    | Required | Description                                                         |
| :------------- | :------ | :------- | :----------------------------------------------------------- |
| `msgId`        | String  | Yes       | Message ID.<br/>This ID corresponds to the complete streaming message, and its chunks are distinguished by the `seq` field.<br/>**Omit for the first chunk and include for subsequent chunks**: Leave this field empty when initiating a streaming message. For subsequent chunks, pass the `msgId` returned by the first API call. |
| `msg`          | String  | Yes       | Text content of the current chunk. The total length of the complete streaming message cannot exceed 128 KB.    |
| `seq`          | Int | Yes       | Chunk sequence number. A streaming message is split into multiple chunks that are sent in order. The first chunk has sequence number `0`, and subsequent sequence numbers increase incrementally so that the chunks can be combined into the original message. |
| `finish`       | Bool    | No       | Indicates whether the current chunk is the last one.<br/> - (Default) `false`: No.<br/> - `true`: Yes.<br/>Set this parameter to `true` when sending the last chunk. If you send a new chunk with the same `msgId` after the message has ended, error code 14035 is returned. |
| `finishReason` | Int | No       | Custom end reason code, which takes effect only when `finish` is `true`. It can indicate scenarios such as normal completion or termination. |
| `type`         | String  | No       | Text format type. Include it only in the first chunk.<br/> - (Default) `text`: Plain text.<br/> - `markdown`: Markdown format. |

### Response example

```json
{
    "path": "/stream_message/user",
    "uri": "https://XXXX/XXXX/XXXX/stream_message/user",
    "timestamp": 1766740077265,
    "organization": "113230417254974",
    "application": "dd7f0328-5f3e-XXXX-XXXX-2e0434c5931b",
    "action": "post",
    "data":
    {
        "msgId": "1499696395467098072"
    },
    "duration": 74,
    "applicationName": "moderation"
}
```

```json
{
    "error": "message_send_error",
    "exception": "MessageSendException",
    "timestamp": 1766737700561,
    "duration": 1,
    "error_code": 14035,
    "error_description": "streaming message has already finished"
}
```

### Response body fields

If the returned HTTP status code is `200`, the request is successful. The `data` field in the response body is described below:

| Parameter | Type   | Description            |
| :------------------- | :----- | :-------------------------------------------- |
| `data`  | JSON | Response content. |
| `data.msgId`  | String | Unique ID of the streaming message. **It is returned only in the response to the first chunk request**. Subsequent chunk requests must include this `msgId`. |

The other fields in the response body are described below:

| Field | Type   | Description                                                         |
| :---------------- | :----- | :----------------------------------------------------------- |
| `path`            | String | Request path, which is part of the request URL and does not require your attention. |
| `uri`             | String | Request URL.                                             |
| `timestamp`       | Long   | Unix timestamp in milliseconds.                      |
| `organization`    | String | Unique organization identifier, identical to the `org_name` request parameter and assigned by EasyIM to each organization. |
| `application`     | String | Unique identifier of the app in the EasyIM system. It is automatically generated by the system and does not require processing. |
| `action`          | String | HTTP method corresponding to the request.                                       |
| `duration`        | Int    | Total duration from initiating the request to receiving the response, in milliseconds.                         |
| `applicationName` | String | App name entered when the app was created in the EasyIM Console, identical to the `app_name` request parameter. |

If the returned HTTP status code is not `200`, the request fails. See [Response status codes](#error-code) for possible causes.

### Error code

| HTTP status code | Error message                                  | Description                                                         |
| :---------- | :---------------------------------------- | :----------------------------------------------------------- |
| 14001       | param from can't be empty                 | `from` is required and cannot be empty.                                |
| 14002       | param to can't be empty                   | `to` is required and cannot be empty.                                  |
| 14005       | param body can't be empty                 | `body` is required and cannot be empty.                                |
| 14030       | param body.seq is illegal                 | The `body.seq` parameter is invalid. This error occurs if the parameter is omitted or its value is less than `0`.  |
| 14031       | can not find streaming message by msgId      | No streaming message corresponding to the specified `msgId` was found. For example, an incorrect or no longer existing `msgId` was passed when sending the second chunk. |
| 14032       | streaming message total length exceeds limit | The total length of the streaming message exceeds the 128 KB limit.                           |
| 14033       | streaming message chunk interval timeout     | The interval between two adjacent chunks exceeds 30 seconds.                           |
| 14034       | streaming message total timeout              | The total duration for sending the entire streaming message exceeds 30 minutes.                       |
| 14035       | streaming message has already finished       | The streaming message transmission is complete. This error occurs if another chunk is sent for the same message after `finish` has been set to `true`. |
| 14036       | streaming message from user mismatch         | The `from` value in the current request differs from the value passed in the first chunk.             |
| 14037       | streaming message to user mismatch           | The `to` value in the current request differs from the value passed in the first chunk.               |
| 14038       | streaming message chunk seq too small        | The `seq` value of the current chunk must be greater than that of the previous chunk. Chunk sequence numbers must increase consecutively. |
