# Retrieve Chat Group Members by Page

## Feature overview

- Retrieve the chat group member list by page.
- Chat group roles, listed from highest to lowest permission level, include group owner, chat group admin, and regular chat group member.
  - The group owner has all chat group permissions.
  - Chat group admins can manage the group blocklist, chat group allowlist, and mute list.
  - A chat group can have up to 100 owners and admins in total. Because a chat group has one owner, it can have up to 99 admins.

## Call frequency limit

100 calls/second/App Key

## Request URL

```http
GET https://{host}/{org_name}/{app_name}/chatgroups/{group_id}/users?pagenum={N}&pagesize={N}&joined_time={true/false}
```

| Parameter       | Type | Required | Description            |
| :--------- | :--- | :------- | :------------------- |
| `group_id`  | Int    | Yes       | Chat group ID. |
| `pagenum`  | Int  | No       | Current page number. By default, it starts from page 1.                           |
| `pagesize` | Int  | No       | Number of chat group members to return per page. The value range is [1,1000], and the default is `1000`. If the value exceeds `1000`, the server still returns 1000 chat group members. |
| `joined_time` | Bool  | No       | Whether to return the time when the user joined the chat group: <br/> - `true`: Return the time. <br/> - (Default) `false`: Do not return the time. |

For details about other parameters in the request URL, see [Request URL parameters](overview.html#request-url).

## Request example

```shell
# Replace <YourAppToken> with the App Token generated on your server

curl -X GET https://XXXX/XXXX/XXXX/chatgroups/10XXXX85/users?pagesize=1000&pagenum=1&joined_time=true'  \
-H 'Authorization: Bearer <YourAppToken>'
```

## Response body fields

If the returned HTTP status code is `200`, the request is successful. The `data` field in the response body is described below:

| Field          | Type   | Description                                        |
| :------------ | :----- | :------------------------------------------ |
| `data` | JSON Array | Chat group member information.  |
| - `owner`  | String | The user ID of the group owner. For example: {"owner": "user1"}.   |
| - `member`  | String | User IDs of chat group admins and regular members. For example: {"member": "user3"}. |
| - `joined_time` | String | Time when the user joined the chat group. |

The other fields are described below:

| Field          | Type   | Description                                        |
| :------------ | :----- | :------------------------------------------ |
| `action`          | String | Request method. |
| `application`     | String | Unique identifier of the app in the system. It is generated by the system and does not require your attention. |
| `params`        | JSON | Query parameters.  |
|  - `joined_time` | Bool  | Whether to return the time when the user joined the chat group: <br/> - `true`: Return the time. <br/> - `false`: Do not return the time. |
|  - `pagesize`        | Array | The desired number of chat group members per page.  |
|  - `pagenum`        | Array | Current page number.  |
| `uri`                | String | Request URL.   |
| `entities`           | JSON   | Response entity.  |
| `timestamp`          | Long   | The Unix timestamp of the HTTP response in milliseconds.   |
| `duration`           | Long   | The length of time from sending the HTTP request to the response, in milliseconds.     |
| `organization`       | String | Unique identifier assigned by EasyIM to each company (organization), identical to the `org_name` request parameter.      |
| `applicationName`    | String | App name entered when you created the app in the Easemob Console, identical to the `app_name` request parameter. |
| `count` | Int | Number of chat group members returned by this request. |

If the returned HTTP status code is not `200`, the request fails. See [Error code](#error-code) for possible causes.

## Error code

If the returned HTTP status code is not `200`, the request fails and one of the following error codes may be returned:

| HTTP status code        | Error type | Error message          | Possible cause | Recommendation |
| :----------- | :--- | :------------- | :----------- | :----------- |
| 401     | unauthorized | Unable to authenticate (OAuth) | The token is invalid, expired, or incorrect. | Use a new token. |
| 404     | service_resource_not_found | do not find this group:XX | The chat group does not exist. | Use a valid chat group ID. |

For other errors, see [Response status codes](error.html) for possible causes.
