# Download a File Thumbnail

This article describes how to call the REST API to download thumbnails of image and video files.

## Feature overview

- When you receive an image or video message, you can download the image or video thumbnail first and then download the original image or video file when needed.
- The only difference between downloading a thumbnail and downloading the original file is that the thumbnail request includes `thumbnail: true` in the request header. When the server receives a request header containing this field, it returns the thumbnail. Otherwise, it returns the original file.
- The file ID (`file_uuid`) and file access key (`share-secret`) returned in the [Upload a file](message_upload_file.html#response-body-fields) response can be used to download the attachment. For details, see [Attachment message sending workflow](message_single.html#attachment-message-sending-workflow). If restricted access was enabled when the file was uploaded by setting `restrict-access=true`, you must pass `share-secret` when downloading either the original file or its thumbnail.

## Call frequency limit

100 requests per second per App Key

## Request URL

```http
GET https://{host}/{org_name}/{app_name}/chatfiles/{file_uuid}
```

| Parameter        | Type   | Required | Description                            |
| :---------- | :----- | :------- | :------------------------------ |
| `file_uuid` | String | Yes       | The UUID generated by the server for the thumbnail file. You can obtain the file UUID from the response of the [Upload a file](message_upload_file.html#response-body-fields) API. |

For descriptions of the parameters in the request URL, see [Request URL parameters](overview.html#request-url).

## Request example

```shell
# Replace <YourAppToken> with the app token generated on your server

curl -X GET 'https://XXXX/XXXX/XXXX/chatfiles/7f456bf0-ecb2-11e8-b630-777db304f26c' \
-H 'Accept: application/octet-stream'   \
-H 'Authorization: Bearer <YourAppToken>'   \
-H 'share-secret: f0Vr-uyyEeiHpHmsu53XXXXXXXXZYgyLkdfsZ4xo2Z0cSBnB'  \
-H 'thumbnail: true' 
```

## Request header fields

For descriptions of the `Accept` and `Authorization` fields, see [Request header field descriptions](overview.html#request-header-fields).

| Parameter            | Type   | Required       | Description       |
| :-------------- | :----- | :--------------------- | :------------------ |
| `thumbnail`     | Bool   | No      | Whether to download the thumbnail:<ul><li> `true`: Yes. Download the thumbnail.</li><li>(Default) `false`: No. Download the original file.</li></ul> <Container type="notice" title="Notice">If this parameter is empty, the original file is downloaded.</Container> |
| `share-secret`  | String | No    | The thumbnail access key. If access to the image was restricted when it was uploaded by setting `restrict-access` to `true`, this key is required to download the thumbnail. After successfully uploading the image, obtain the key from the response body of [Upload a file](message_upload_file.html). |

## Response example

```json
{
  // Thumbnail information
}
```

A return value of `401` indicates that the request is unauthorized, for example, because the token is missing, incorrect, or expired.

```json
{
  "error": "auth_bad_access_token",
  "timestamp": 1542350943210,
  "duration": 0,
  "exception": "org.apache.usergrid.rest.exceptions.SecurityException",
  "error_description": "Unable to authenticate due to corrupt access token"
}
```

## Response body fields

If the returned HTTP status code is 200, the request is successful. For the parameters and their descriptions, see [Upload a file](message_upload_file.html).

If the returned HTTP status code is not `200`, the request fails. See [Response status codes](error.html) for possible causes.

## Error code

If the returned HTTP status code is not `200`, the request fails and may return the following error codes:

| HTTP status code | Error type               | Error message                  | Possible cause    | Recommendation      |
|:---------|:-------------------|:----------------------|:--------|:----------|
| 404      | entity_not_found | file may not exists | The specified `file_uuid` does not exist. | Enter the correct path parameter `file_uuid`. |
| 404      | file_expired | file xxxxx is expired | The file has expired. | By default, message attachments such as images, audio, video, and other files can be stored for 7 days. To increase this limit, contact the EasyIM business manager.|

For other errors and their possible causes, see [Response status codes](error.html).
