# Bind and Unbind Push Information

## Feature overview

When messages are pushed, a device is bound to push information, including the device ID, push certificate, and device token.

- Device ID: The unique identifier assigned by the SDK to each device.

- Device token: A push token provided by a third-party push service. The token identifies each app on each device. The third-party push service uses it to determine the target device, forwards the message to the device, and the device then notifies the app. For example, for FCM push, the device token is the registration token generated by the FCM SDK for the client app instance when your app is launched for the first time.

- Push certificate: A push certificate is provided by a third-party push service. Each app corresponds to one push certificate.

The user obtains the device token and certificate name from the third-party push server and uploads them to the EasyIM server. The server pushes messages to the user based on the device token.

You can call this API to bind or unbind a device and its push information.

## Call frequency limit

The aggregate call frequency limit for this API, other user account management APIs, and offline push APIs is 100 requests per second per App Key. For details, see [API call frequency limits](limitationapi.html#user-account-management).

## Request URL

```
PUT https://{host}/{org_name}/{app_name}/users/{userId}/push/binding
```

| Parameter       | Type   | Description   | Required | 
| :--------- | :----- | :------- | :------------------ |
| `userId` | String | User ID of the user whose device and push information to bind or unbind.    | Yes       | 

For details about the parameters in the request URL, see [Request URL parameters](overview.html#request-url).

## Request example

**Binding request**

```shell
curl -X PUT 'https://XXXX/XXXX/XXXX/users/XXXX/push/binding' \
-H 'Content-Type: application/json' \
-H 'Authorization: Bearer <YourAppToken>' \
-d '{    
    "device_id": "8ce08cad-XXXX-XXXX-86c8-695a0d247cda",    
    "device_token": "XXXX",    
    "notifier_name": "104410638"
}'
```

**Unbinding request**

```shell
curl -X PUT 'https://XXXX/XXXX/XXXX/users/XXXX/push/binding' \
-H 'Content-Type: application/json' \
-H 'Authorization: Bearer <YourAppToken>' \
-d '{    
    "device_id": "8ce08cad-XXXX-XXXX-86c8-695a0d247cda",    
    "device_token": "",    
    "notifier_name": "104410638"
}'
```

## Request header fields

For details about the `Content-Type`, `Accept`, and `Authorization` fields, see [Request header fields](overview.html#request-header-fields).

## Request body fields

| Parameter            | Type   | Description                                                         | Required |
| :-------------- | :----- | :----------------------------------------------------------- | :------- |
| `device_id`     | String | Mobile device identifier used by the server to identify the device and bind or unbind push information. | Yes       |
| `notifier_name` | String | Push certificate name.<br/> - The specified certificate name must match the certificate name entered on the **Add Push Certificate** page of the Easemob Console. Otherwise, push fails.<br/> - If `notifier_name` is empty, the current device is unbound from all push information. | Yes       |
| `device_token`  | String | Push device token. Incorrect information causes push to fail, and the server automatically unbinds it. If `device_token` is empty, the binding between the current user's current device ID and the current certificate name is removed. | Yes       |

**Binding response**

{

  "entities": [ 
    {            
      "device_id": "8ce08cad-9369-XXXX-XXXX-695a0d247cda",

**Unbinding response**

```json
{    
  "timestamp": 1688030767345,    
  "entities": [],    
  "action": "put",    
  "duration": 24
}
```

## Response body fields

If the returned HTTP status code is `200`, the request is successful. The response body contains the following fields:

| Field        | Type   | Description                                                         |
| :---------- | :----- | :----------------------------------------------------------- |
| `entities`  | Array  | List of push information bound to the current device. If the device has no push binding information after the binding request is sent, an empty list is returned. |
| - `device_id`     | String | Mobile device identifier used by the server to identify the device and bind or unbind push information. |
| - `notifier_name` | String | Push certificate name. | 
| - `device_token`  | String | Push device token.|
| `timestamp`       | Long   | Unix timestamp in milliseconds. |
| `action`          | String | Request method. |
| `duration`        | Int    | Duration from sending the request to receiving the response, in milliseconds. |

## Error code

If the returned HTTP status code is not 200, the request fails. See [Common error codes](push_error.html) for possible causes.
