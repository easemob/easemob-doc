## Retrieve historical messages API

### Feature overview

You can retrieve records of historical messages sent by users from the server.

- A single request retrieves records of historical messages sent within one hour from the specified start time.
- You can retrieve historical message records from up to the past 3 days. To increase this limit, contact the Easemob business team.
- When the platform distributes a large volume of messages, the server needs time to generate historical message records. We recommend retrieving these records after 24 hours. If timeliness is important, use the [post-delivery callback service](callback_postsending.html).
- Calling the REST API to [delete a conversation unilaterally](conversation_delete.html) or [delete roaming messages unilaterally](message_delete_roam_single_msgid.html) does not affect historical message records retrieved through this API.

### Call frequency limit

10 calls/minute/App Key

### Request URL

```http
GET https://{host}/{org_name}/{app_name}/chatmessages/{time}
```

| Parameter | Type   | Required | Description         |
| :----- | :----- | :------- | :------------- |
| `time` | String | Yes       | Start time for querying historical message records.<br/> - Chinese mainland cluster: Uses Beijing time in yyyyMMddHH format. For example, if `time` is `2018112717`, the query covers historical messages from 17:00 to 18:00 on November 27, 2018.<br/> - Overseas cluster: Uses UTC in yyyyMMddHH format. Convert the time according to your time zone. |

For details about other parameters in the request URL, see [Request URL parameters](overview.html#request-url).

### Request example

```shell
# Replace <YourAppToken> with the App Token generated on your server

curl -X GET 'https://XXXX/XXXX/XXXX/chatmessages/2018112717'    \
-H 'Accept: application/json'    \
-H 'Authorization: Bearer <YourAppToken>' 
```

### Request header fields

For details about the `Content-Type`, `Accept`, and `Authorization` fields, see [Request header fields](overview.html#request-header-fields).

### Response example

```json
{
  "action": "get",
  "application": "8be024f0-XXXX-XXXX-b697-5d598d5f8402",
  "uri": "'https://XXXX/XXXX/XXXX/chatmessages/2018112717",
  "data": [
    {
      "url": "https://XXXX?Expires=1543316122&OSSAccessKeyId=XXXX&Signature=XXXX"
    }
  ],
  "timestamp": 1543314322601,
  "duration": 0,
  "organization": "XXXX",
  "applicationName": "testapp"
}
```

### Response body fields

If the returned HTTP status code is `200`, the request is successful. The `data` field in the response body is described below:

| Parameter       | Type   | Description     |
| :--------- | :----- | :------------------ |
| `data`  | JSON   | Details of the retrieved data.  |
| - `url` | String | Download URL for the historical message records. The URL consists of the storage address of the historical message records, the expiration Unix timestamp (`Expires`, in seconds), the third-party cloud storage access key (`OSSAccessKeyId`), and the third-party cloud storage verification signature (`Signature`). The URL is valid only for a limited time. Use it to download the chat history file promptly. If the URL expires, the download fails and you must call this API again to obtain a new URL. |

The other fields are described below:

| Parameter              | Type   | Description                                                                           |
| :---------------- | :----- | :----------------------------------------------------------------------------- |
| `action`          | String | Request method.                                                                     |
| `application`     | String | Unique identifier of the app in the system. This identifier is generated by the system and does not require your attention.                     |
| `uri`             | String | Request URL.                                                                     |
| `timestamp`       | Long   | Unix timestamp in milliseconds.                                                      |
| `duration`        | Int    | Duration from sending the request to receiving the response, in milliseconds.                                           |
| `organization`    | String | Unique identifier assigned by EasyIM to each company (organization), identical to the `org_name` request parameter. |
| `applicationName` | String | App name entered when you created the app in the Easemob Console, identical to the `app_name` request parameter. |

If the returned HTTP status code is not `200`, the request fails. See [Response status codes](error.html) for possible causes.

### Error code

If the returned HTTP status code is not `200`, the request fails and one of the following error codes may be returned:

| HTTP status code | Error type   | Error message      | Possible cause    | Recommendation   |
|:---------|:-------------------|:--------------------|:---------|:--------------|
| 400      | illegal_argument | illegal arguments: appkey: XXXX#XXXX, time: xxxxxx | The `time` request parameter is in an incorrect format.  | Enter a valid `time` request parameter in UTC using the ISO 8601 standard and yyyyMMddHH format. For example, if `time` is `2018112717`, the query covers historical messages from 17:00 to 18:00 on November 27, 2018. For an overseas cluster that uses UTC, convert the time according to your time zone. |
| 400      | illegal_argument | illegal arguments: appkey: XXXX#XXXX, time: xxxxxx, maybe chat message history is expired or unstored" | The historical file for the period corresponding to `time` has expired or has not yet been stored. The cloud storage duration for messages depends on your product plan. For details, see [Message storage duration limits](/product/limitation.html). | Enter a valid `time` request parameter. |
| 404      | storage_object_not_found | Failed to find chat message history download url for appkey: XXXX#XXXX, time: xxxxxx" | No historical file exists for the period corresponding to `time`.      | If you are certain that historical messages exist within the specified period, contact [Easemob technical support](mailto:support@easemob.com). |

## Historical message content

After successfully querying historical message records, you can access the URL to download the historical message record file and view its contents.

A historical message record contains the following fields:

| Parameter        | Type   | Description              |
| :---------- | :----- | :---------------------- |
| `msg_id`    | String | Message ID.       |
| `timestamp` | Long   | UNIX timestamp when the message was sent, in milliseconds and in UTC.         |
| `direction` | String | Message direction. The value is `outgoing`, indicating a message sent by the current user. |
| `to` | String | Internal field that you can ignore. |
| `from` | String | Internal field that you can ignore. |
| `chat_type` | String | Conversation type:<br/> - `chat`: One-to-one chat.<br/> - `groupchat`: Group chat.<br/> - `chatroom`: Chat room. |
| `payload`   | JSON   | Message details, such as message extensions.   |
| `payload.from`      | String | User ID of the message sender.       |
| `payload.to`        | String | Message recipient:<br/> - For a one-to-one chat, the recipient user ID.<br/> - For a group chat, the chat group ID.<br/> - For a chat room, the chat room ID.  |

Historical message records are in JSON format. Example:

```json
{
  "msg_id": "5I02W-XX-8278a",
  "timestamp": 1403099033211,
  "direction": "outgoing",
  "to": "XXXX",
  "from": "XXXX",
  "chat_type": "chat",
  "payload":
  {
    "bodies": [    {
      // The different message types are described below
      }
      ],
      "ext":
      {
        "key1": "value1",              ...        },
      "from":"XXXX",
      "to":"XXXX"
  }
}
```

### Text messages

The `bodies` field of a text message contains the following fields:

| Parameter | Type   | Description                             |
| :----- | :----- | :------------------------------- |
| `msg`  | String | Message content.                       |
| `type` | String | Message type. The value for a text message is `txt`. |

Example

```json
"bodies": [{"msg":"welcome to easemob!", "type":"txt"}]
```

### Image messages

The `bodies` field of an image message contains the following fields:

| Parameter          | Type   | Description                                                                              |
| :------------ | :----- | :-------------------------------------------------------------------------------- |
| `file_length` | Long   | Image attachment size in bytes.                                                        |
| `filename`    | String | Image filename, including the filename extension.                                                    |
| `secret`      | String | Image file access key. This field is present if file access restrictions were set during [file upload](message_upload_file.html). |
| `size`        | JSON   | Image dimensions in pixels.<br/> - `height`: Image height.<br/> - `width`: Image width.   |
| `type`        | String | Message type. The value for an image message is `img`.                                                      |
| `url`         | String | Image URL.                                                                   |

Example

```json
{
  "bodies": [
    {
      "file_length": 128827,
      "filename": "test1.jpg",
      "secret": "DRGM8OZrEeO1vaXXXXXXXXHBeKlIhDp0GCnFu54xOF3M6KLr",
      "size": {
        "height": 1325,
        "width": 746
      },
      "type": "img",
      "url": "https://XXXX/XXXX/XXXX/chatfiles/65e54a4a-XXXX-XXXX-b821-ebde7b50cc4b"
    }
  ]
}
```

### Custom messages

The `bodies` field of a custom message contains the following fields:

| Parameter          | Type   | Description                                             |
| :------------ | :----- | :----------------------------------------------- |
| `customExts`/`v2:customExts`  | Array/JSON     | User-defined event attributes. This parameter is optional and can be omitted when not needed.<br/> - `customExts` is the legacy parameter. It is an array that can contain up to 16 elements.<br/> - `v2:customExts` is the new parameter. It is of the Map<String,String> type and can contain up to 16 elements. The new parameter is recommended. |
| `customEvent` | String | Custom event type.                                 |
| `type`        | String | Message type. The value for a custom message is `custom`.                |

Example custom message format:

```json

"bodies": 
[
    {
        "v2:customExts": {
            "name": "flower",
            "size": "16",
            "price": "100"
        },
        "customExts": [
            {
                "name": "flower"
            },
            {
                "size": "16"
            },
            {
                "price": "100"
            }
        ],
        "customEvent": "gift_1",
        "type": "custom"
    }
]
```

### Combined messages

The `bodies` field of a combined message contains the following fields:

| Parameter          | Type   | Description                                             |
| :------------ | :----- | :----------------------------------------------- |
| `combineLevel`  | Int   | Number of nesting levels in the combined message. |
| `file_length` | Int | Combined message attachment size in bytes.               |
| `filename`        | String | Combined message attachment name.     |
| `secret`        | String | Access key for the combined message attachment. This field is present if file access restrictions were set during [file upload](message_upload_file.html).  |
| `subType`        | String | Indicates that the message is a combined message.                |
| `summary`        | String | Summary of the combined message.                |
| `title`        | String | Title of the combined message.                |
| `url`        | String | URL of the combined message attachment. You can access this URL to download the attachment.                |

For example, the following is the format of a combined message whose source messages include a text message, an image message, and a file message:

```json
"bodies": 
[
   {
      "combineLevel": 1,
      "file_length": 550,
      "filename": "17289718748990036",
      "secret": "a_OTmoq6Ee-CygH0PRzcUyFniZDmSsX1ur0j-9RtCj3tK6Gr",
      "subType": "sub_combine",
      "summary": ":yyuu\n:[图片]\n:[文件]\n",
      "title": "聊天记录",
      "url": "https://XXXX/XXXX/XXXX/chatfiles/6bf39390-8aba-11ef-a8ae-6f545c50ca23"
    }
]
```
